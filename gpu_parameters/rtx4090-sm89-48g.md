## SM、寄存器与共享内存资源

以下资源由 2026-10-07 对同一 UUID 的 CUDA Driver 属性查询确认；架构派生项单独标明。容量单位 KiB/MiB 为二进制单位，性能 GB/s 使用十进制单位。

| 资源 | 本卡值 / 上限 |
|---|---:|
| Warp 大小 | 32 threads |
| 每 SM 最大驻留线程 / warp | 1536 / 48（warp 数由线程数除以 32 得到） |
| 每 SM 最大驻留 block | 24 |
| 每 block 最大线程数 | 1024 |
| 每 SM 32-bit 寄存器数量 | 65536，即 256 KiB |
| 每 block 32-bit 寄存器上限 | 65536 |
| 每 SM shared memory 上限 | 102400 Byte，即 100 KiB |
| 每 block shared memory 默认 / opt-in 上限 | 49152 / 101376 Byte，即 48 / 99 KiB |
| Constant memory | 65536 Byte，即 64 KiB |
| CUDA cores（架构派生） | 128 SM × 128/SM = 16384 |
| 第四代 Tensor Cores（架构派生） | 128 SM × 4/SM = 512 |

Ada 架构资料给出每 SM 四个 warp scheduler/处理分区、128 KiB 统一 L1/shared/texture 容量，以及每线程最多 255 个 32-bit 寄存器。统一缓存与 shared memory 共享容量，不能将 128 KiB L1 和 100 KiB shared 当作独立可叠加资源。大于 48 KiB/block 的 shared memory 需要动态分配并显式 opt-in。

这些是硬件资源上限；实际驻留还取决于 kernel 的寄存器、shared memory、线程数及分配粒度。128 SM 不意味着任意小 grid 都能用满整卡，100% GPU utilization 也不证明所有 SM 或计算管线饱和。

## 未观察到温度限频的计算吞吐与 Ridge

全部为 dense，无 2:4 sparsity。乘加按 2 operations 计数；浮点吞吐为 TFLOP/s，整数为 TOPS。Ridge 使用同批基础测试的 Triad **938.066131 GB/s**，计算为 `throughput_in_tera × 1000 / bandwidth_in_giga`。FP8/INT8 补充测试复用该带宽，没有另测带宽。

| 输入精度 | 累加 → 输出 | Roof 胜出规模 | 实测 Compute Roof | Ridge | 独立持续测试板卡 W |
|---|---|---:|---:|---:|---:|
| FP32 | FP32 → FP32 | 8192³ | 55.50 | 59.16 FLOP/Byte | 376.1¹ |
| FP16 | FP32 → FP16 | 8192³ | 168.58 | 179.71 FLOP/Byte | 未测 |
| FP16 | FP16 → FP16 | 16384³ | 290.74 | 309.93 FLOP/Byte | 326.6 |
| FP8 E4M3 × E4M3 | FP32 → FP16 | 16384³ | 343.61 | 366.30 FLOP/Byte | 376.7 |
| signed INT8 × INT8 | INT32 → INT32 | 16384³ | **635.70 TOPS** | **677.67 OP/Byte** | **399.9** |

¹ FP32 Roof 来自 8192³，功耗来自 16384³ 的独立 30 秒负载；两者不应当作同一测量窗口的能效对照。该 16384³ 持续吞吐为 54.06 TFLOP/s。FP16-FP32 与 FP8 的输出确实为 FP16，不能与 FP32 输出的实现直接混用性能数字。

本版本 TF32、BF16、FP8 E5M2、FP8-FP16 累加、INT4、FP64 的 Compute Roof 未测。未建立本机独立验证的严格物理峰值；以上数值是固定规模、有限实现下达到的吞吐参考，不能保证任意 shape、layout 或业务输入达到该值。

## 测试实现与数值边界

- 比较 8192³、16384³；每种规模至少 5 次调用预热，3 轮各至少 1 秒。Roof 取两个规模三轮中位数中的较高者，不是穷举算法后的全局最优。
- FP32、两种 FP16 使用 cuBLAS 默认算法、NN column-major，alpha=1、beta=0。FP32 显式 `CUBLAS_COMPUTE_32F_PEDANTIC` 排除 TF32。输入 A/B 为转换到目标类型的常量 0.001。
- FP8 使用 cuBLASLt TN column-major、首个 heuristic、64 MiB workspace 上限，scalar scales=1、`FAST_ACCUM=0`、FP32 累加和 FP16 输出；A/B 常量 0.125。
- INT8 使用 `cublasGemmEx` 默认 TN column-major 路径、signed INT8 输入 A=1/B=2、INT32 累加及输出。历史 NN 低吞吐探针不作为本画像的 INT8 Roof。
- CUDA event 按批次计 GPU 运算时间，初始化、结果抽查、CPU 开销和量化准备不计入吞吐；不包括 H2D/D2H 或业务 E2E。
- FP32/FP16 只检查首个输出，FP8/INT8 各检查 5 个位置。常量输入及抽查覆盖很有限，不等于完整矩阵校验、量化误差审计或模型正确性验收。

这些实现、常量输入与热条件是性能结论的适用前提。输入分布可影响功耗及可保持的时钟，不能把这里的功耗作为吞吐利用率的固定换算表。

## 显存带宽

| 测试 | 三轮中位带宽 | 独立持续测试 Board W | 流量口径 |
|---|---:|---:|---|
| D2D Copy | 919.66 GB/s | 282.6 | 读＋写，8 Byte/FP32 元素 |
| Triad | **938.07 GB/s** | 284.7 | `A=B+C×D`，三读一写，16 Byte/FP32 元素 |

每数组 512 MiB，约为 L2 的 7.11 倍；Copy 一次计 1 GiB，Triad 一次计 2 GiB 读写合计。Triad 每元素一条 FMA，2 FLOP，AI=0.125 FLOP/Byte。这里是算法字节数/GPU 时间的有效带宽，未由 DRAM 硬件交易计数核验。

这两项持续窗口分别为 SM 2700 MHz、核心约 62.1/61.0°C，SW Power Cap 和 SW/HW Thermal Slowdown 均为 0%。Ridge 是基于该 DRAM 带宽和所选计算实现的模型拐点；高于它仍可能受寄存器、shared memory、指令、驻留、依赖或提交成本限制。没有对应精度完整 AI sweep 时，参考包络不能当作该精度的扫描实测。

## 指令能力与未验证项

- 原始库调用与输出抽查支持上述 FP32、FP16、FP8 E4M3、INT8 路径曾成功执行；没有代表 GEMM 的 NCU 计数或 SASS 证据确认整卡 SM 覆盖和具体管线效率。
- 同一 SM89 的已有编译探针支持 FP16/BF16/TF32、FP8 E4M3/E5M2、INT8/INT4/binary warp-level MMA 及 `cp.async`。探针只编译、未运行，不据此建立性能 Roof 或框架支持结论。
- SM89 不原生支持 FP6/FP4 Tensor 路径、Hopper TMA 或 Blackwell TMEM/`tcgen05`。INT4 是整数格式，不是 FP4；`cp.async` 不能称作 TMA。TMA 编译探针因要求 SM90 而失败。
- 已有 NCU 预检查返回 `ERR_NVGPUCTRPERM`。SM coverage、CTA/waves、Tensor/FP32 pipeline、DRAM 实际字节数为待验证项；计数器权限与普通 CUDA 执行能力分别判断。
